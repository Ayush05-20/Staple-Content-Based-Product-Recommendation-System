# Staple — Content-Based Product Recommender

Django + PostgreSQL + TF-IDF/cosine-similarity content-based recommendations,
built on a real Kaggle beauty/personal-care product dataset (1,000 products,
cleaned, with real images). Session-based auth (Django's built-in system).

The model is **already trained** — `ml_models/similarity_matrix.pkl` and
`ml_models/product_ids.pkl` are included, so recommendations work the moment
you import the bundled CSV. Everything below just gets it running on your
machine.

---

## 0. What you need installed first

- Python 3.10+ (`python3 --version`)
- PostgreSQL 14+ running locally (`psql --version`)

If you don't have PostgreSQL yet:
- **Mac**: `brew install postgresql@16 && brew services start postgresql@16`
- **Windows**: install from https://www.postgresql.org/download/windows/
- **Linux**: `sudo apt install postgresql postgresql-contrib`

## How the recommendation engine actually works

- `store/models.py` — `Product.content_text` combines name + category +
  brand + tags into one string per product. That string is what the model
  "reads."
- The `.pkl` files in `ml_models/` are the **pre-computed output** of:
  1. Turning every product's `content_text` into a TF-IDF vector
  2. Computing cosine similarity between every pair of products
  3. Saving that NxN score grid (`similarity_matrix.pkl`) plus a list mapping
     each row to a real `Product.id` (`product_ids.pkl`)
- `store/recommend.py` just **loads** those two files and looks up scores —
  no training happens inside Django itself. This is why the "similar
  products" section loads instantly even though the underlying computation
  (TF-IDF + cosine similarity across 1,000 products) would be too slow to
  redo on every single page view.

## Adding your own products (e.g. a different category like electronics)

You can add anything you want through `/admin/` — Product has no restriction
to beauty items. But remember what we covered:

1. A product added through `/admin/` **won't appear in any recommendations**
   until you retrain — the `.pkl` files are a frozen snapshot from whenever
   they were last generated.
2. Content-based filtering only connects items with **overlapping
   vocabulary**. A laptop won't get recommended on a nail-polish page (and
   shouldn't) — it'll only show up as similar to *other electronics* you add,
   once retrained.

## Auth summary

- Built entirely on Django's included auth system — no JWT, no DRF.
- `/register/` — custom view using `UserCreationForm`
- `/login/` `/logout/` — Django's built-in `LoginView`/`LogoutView`
- `/admin/` — only your superuser (or anyone you mark `is_staff`) can reach
  this; regular registered users cannot access it or perform CRUD.

## Where the data came from

`data/products_import.csv` is a cleaned sample (1,000 rows, deduplicated,
first image URL only) taken from a Kaggle Walmart beauty/personal-care
product export. `price` isn't in the source data, so every imported product
defaults to `0` — feel free to set real prices through `/admin/` if you want
that field to mean something.
